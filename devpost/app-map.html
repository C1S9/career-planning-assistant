Technical reference · Current demo

From a conversation
to a checked plan.

A Streamlit page uses the current conversation to request career exploration tasks from DeepSeek. Python checks the returned fields and dates before displaying a marked result.

This is a reference route. It does not claim that a hands-on code tour was completed.

One action, end to end

01 · InputChoose daysapp.py

Save the selected period and the existing conversation.

02 · External serviceRequest JSONagent.generate_plan

DeepSeek generates structured task data.

03 · Program rulesCheck the planmodels.parse_plan

Require valid fields and dates inside the saved period.

04 · Visible resultShow checked tasksformat_plan → app.py

Render the tasks with an application-owned checked label.

A structural failure permits one correction request. Provider errors stop immediately. Invalid plans do not receive a checked label. Overlapping tasks are allowed.

A three-stop reference route

STOP 01 · The button

app.py

Search for Create checked plan and queue_message. The chosen number of days becomes a saved request value, so a later rerun or retry cannot silently substitute a new period.

Where the conversation lives

st.session_state.messages holds this browser session's transcript. New Conversation clears it. There is no application conversation database.

STOP 02 · The request

agent.py → generate_plan

The existing transcript and an exact duration are sent to DeepSeek with JSON instructions. Search for for attempt in range(2): only a structural failure can request one correction.

Where instructions live

prompts.py → PLAN_SYSTEM_PROMPT guides plan generation. SYSTEM_PROMPT guides ordinary chat. A prompt alone cannot prove that dates are valid.

STOP 03 · The check

models.py → parse_plan

Pydantic checks types and required fields. CareerPlan.check_schedule checks dates. parse_plan compares the output duration to the actual selection. format_plan produces readable text.

What the label means

app.py adds schedule_checked after successful parsing. It checks fields and schedule; it does not certify career suitability, vacancy availability, or employment outcomes.

A practice to reuse

Keep the person's choice separate from the model's claim. This app saves the requested duration first, then compares the returned duration and every task against it.

tests/test_plans.py → test_model_cannot_substitute_its_own_period exercises the mismatch. The learner separately reported successful live use. Automated fixtures and a real provider result supply different evidence.

On another project, turn a requirement into a checkable rule before treating generated output as valid.

Run it again

In the project folder on Windows, use the configured Python environment:

.\.venv\Scripts\python.exe -m streamlit run app.py

Open the local address shown in the terminal. Configure the API key privately as described in README.md. The repository contains a placeholder example; the real settings file stays outside Git.

To run the existing simulated-response checks:

.\.venv\Scripts\python.exe -m unittest discover -s tests -v
